A skill is a `SKILL.md` of instructions plus whatever files it points to. Most agents load skills from a local folder, which means every laptop has its own copy and none of them agree. Put the skills on an MCP server instead: one copy, and an update ships when you deploy.

```python
from fastmcp import FastMCP, Skill
from fastmcp.skills.provider import SkillCatalogProvider

release_notes = Skill(
    name="release-notes",
    description="Write release notes from merged pull requests.",
    instructions="# Release notes\n\nGroup changes by theme. Follow template.md.\n",
    files={"template.md": "## Highlights\n\n## Fixes\n"},
)

mcp = FastMCP("Team Skills")
mcp.add_provider(SkillCatalogProvider([release_notes]))
```

That's a skills server. Every client can read `skill://release-notes/SKILL.md` and `template.md` as ordinary resources. Clients that speak the [Skills extension](https://modelcontextprotocol.io/seps/2640-skills-extension) can also call `skills/list` and get each skill's description and a hashed manifest of its files, so a host can offer the skill without an install step. Few hosts do yet, and FastMCP's support is experimental, but you get both from the same provider. Run `fastmcp list server.py --skills` to see what you're serving.

## Where skills come from

A `Skill` is just files. Write it in Python as above, or load what you already have:

```python
from fastmcp import Skill

deploy = Skill.from_directory("skills/deploy")
review = Skill.from_package("my_package", "skills/review")
triage = Skill.from_files({"SKILL.md": "---\nname: triage\ndescription: Triage issues.\n---\n"})
```

Skills are validated when you build them and never change afterward; editing the folder later doesn't touch the loaded skill. The `description` is what an agent reads to decide whether to use the skill, so make it say when.

If your skills live somewhere that changes, like a database, override `load_skills()`. FastMCP calls it once per request:

```python
from fastmcp import Skill
from fastmcp.skills.provider import SkillCatalogProvider


class StoredSkills(SkillCatalogProvider):
    async def load_skills(self) -> list[Skill]:
        rows = [{"SKILL.md": "---\nname: triage\ndescription: Triage issues.\n---\n"}]
        return [Skill.from_files(files) for files in rows]
```

If you're still editing a folder and want changes to show up live, serve it straight from disk with `SkillsDirectoryProvider(path, experimental_skills=True)`. Presets like `ClaudeSkillsProvider` do the same for a coding agent's own skills folder.

## Access control

Discovery never shows a skill the caller can't read. If any of its files is hidden, denied by `check_resource_access` (what [`AuthMiddleware`](/servers/authorization) uses), or shadowed by another resource, the skill drops out of `skills/list`.

## Mounted servers

Skills come along when you [mount](/servers/composition) a server, at the URIs the parent serves them at: `mount(child, namespace="team")` turns `skill://review/` into `skill://team/review/`. If you'd rather choose exactly which providers are discoverable, register the extension yourself with `mcp.add_extension(SkillsExtension(providers=[...]))` from `fastmcp.skills.extension`.

## Read skills from a client

### Install skills into a local agent

Most agents still only read skills from disk. `sync_skills()` copies a server's skills into a local folder, and works with any server that serves skills as resources:

```python
from pathlib import Path

from fastmcp import Client
from fastmcp.utilities.skills import sync_skills

async with Client("http://localhost:8000/mcp") as client:
    await sync_skills(client, Path.home() / ".claude" / "skills", overwrite=True)
```

### Discover skills with the Skills extension

Opt the client into the extension and ask:

```python
from fastmcp import Client
from fastmcp.skills import SkillsClientExtension

client = Client("http://localhost:8000/mcp", extensions=[SkillsClientExtension()])
async with client:
    for skill in await client.list_skills():
        print(skill.uri, skill.frontmatter.description)
```

You get metadata, not content. Read the files you need with `read_resource()`, and check each against its manifest `digest` before trusting it. [`ClientGroup.list_skills()`](/clients/client-groups) does the same across several servers.

## Current limits

- Skills behind a proxy are readable as resources but don't show up in `skills/list`.
- A provider added with a namespace or other transforms isn't discoverable; mount a server instead.
- `directoryRead` isn't implemented.
